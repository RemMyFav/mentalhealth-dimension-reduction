# Sprint 01 Report — Robustness, Human Labels, and Template-Reduced Clustering

## 1. Objectives

This sprint focused on improving confidence in the baseline pipeline by testing robustness and incorporating human annotation for comparison.

Planned objectives:

- **Robustness of semantic mapping anchors**
  - Generate **5 independent definition sets** (8 wellness dimensions each) using LLMs.
  - Re-run semantic mapping using each definition set as prototypes.
  - Test whether assignments are broadly consistent across definition sets.
  - Ideally, compare favorably against **human single-label classifications**.

- **Template-reduced K-means clustering**
  - Re-run K-means clustering after reducing each item into a more “content-only” representation (initially NVO; later improved).
  - Reduce the risk that clustering is driven by repeated questionnaire templates / surface word overlap.
  - Assign an interpretable semantic label to each K-means cluster so cluster meaning can be formalized (clustering only).

- **Human annotation collection (collaborator task)**
  - Human 8-class labeling data is collected to support comparison against model outputs.
  
## 2. Completed Work

### 2.1 Semantic Mapping Robustness (5 LLM Definition Sets)

- Generated **five independent natural-language definition sets** for the 8 wellness dimensions (`dim_difination.csv`).
- Repeated the semantic mapping pipeline using each definition set as semantic anchors and aggregated the assignments.
- Produced a consolidated robustness summary file:
  - `v2_5LLM_confidence_agreement.csv` (agreement levels such as `exact_5of5`, `exact_4of5`, etc.)
- Key takeaway:
  - Mapping is **highly stable** under definition wording variations:
    - **114** questions reached full **5/5 agreement**
    - **32** additional questions had at least one dimension agreed by **4/5**
    - Every question has at least one dimension supported by **4/5**
- The file `dim_definitions.csv` includes definition sets generated by:
	•	Gemini-3.0-Pro
	•	DeepSeek-V3.2
	•	ChatGPT-5.2
	•	Claude-Sonnet-4.5
	•	Llama-4


### 2.2 Template-Reduced K-means Clustering via UD-Based Reduction

- Attempted NVO-only clustering first, but found questionnaire templates still leaked into representations.
- Implemented linguistic reduction using **Stanza + Universal Dependencies (UD)**:
  - Extracted dependency roots and removed grammatical shells (auxiliaries, determiners, etc.) to better isolate semantic content.
- Performed K-means clustering (K=8) on UD-reduced text embeddings.
- Manually inspected clusters and assigned interpretive labels:
  - `["Sleep", "Spiritual", "Relationship", "Relationship", "Feeling", "Physical", "Challenge", "Future"]`
- Exported clustering outputs:
  - `v2_Stanza_Cluster.csv` with columns:
    - `qid`, `dataset`, `text_raw`, `text` (UD-reduced), `cluster_id`, `cluster_type`
  
### 2.3 Human Annotation Integration + Exploratory Dispersion Analysis

- Found coverage mismatch between the original dataset pool and the human questionnaire:
  - Some datasets (e.g., **UCLA PWS**) did not appear in the human annotations.
- Ran an exploratory comparison on the **overlap subset** (87 items) to keep comparisons aligned.
- Compared internal dispersion using entropy-style measures:
  - Human: repeatedly sample 5 annotators from the 28 total and average across repetitions.
  - Models: treat the 5 definition-set runs as a 5-member committee.
- Preliminary observation:
  - Under matched sample sizes (5 vs 5), model dispersion was slightly lower than human dispersion (difference ≈ **0.013 normalized entropy**). See `HumanVSLLM.png`

## 3. Open Questions and Challenges

- **Human test–retest reliability (repeated questions)**
  - The human questionnaire includes repeated items for test–retest reliability.
  - Next step (from Tansu): split repeated items into repetition-1 and repetition-2 and compute Human avg JSD / entropy **separately**, using repeated subsampling (e.g., 5 annotators × 10 repeats).

- **Full human set vs overlap-only**
  - Overlap-only was used for an initial controlled comparison.

- **Reduction criterion definition**
  - Decide whether reduction should be:
    - **Stability-first** (low ambiguity / low dispersion),
    - **Informativeness-first** (max discriminability / downstream validity),
    - or a **weighted combination**.

- **Single-label human data vs multi-label structure**
  - The current human dataset is single-label by design.
  - Multi-label evaluation likely requires collecting a new dataset; for now, keep evaluation consistent with single-label constraints.
